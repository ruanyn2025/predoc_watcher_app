# 岗位浏览器（webapp）

把邮件推送版抓到的岗位变成一个能翻、能搜、能收藏、能提醒的小软件。

与 `../mailer/`（每日邮件推送）**完全独立**：本目录只以**只读**方式读取
`../mailer/state.json`，不写回、不调用它的任何代码。两边可以同时运行，互不影响。

## 启动

双击 `启动.bat`，浏览器会自动打开 <http://127.0.0.1:8765/>。
关掉那个黑色窗口就停止运行。

命令行等价写法：

```
D:\miniforge3\envs\dc1\python.exe app.py
```

| 参数 | 作用 |
|---|---|
| `--no-browser` | 不自动打开浏览器 |
| `--no-refresh` | 启动时不重新读取 state.json |
| `--port 8000` | 换端口 |
| `--verbose` | 打印每条 HTTP 请求，排错用 |

## 四个页面

**首页** —— 自上次「标为已读」以来的新增岗位，按抓取日期分组；顶部是未来 14 天内
到期的收藏提醒，剩 3 天以内会标红。

**历史列表** —— 全部岗位（含已下架）。搜索框跨**领域 / 导师 / 学校学院 / 标题**匹配，
空格分隔的多个词按「同时满足」处理，例如 `labor harvard` 会同时命中领域和机构。
还能按来源、在招状态筛选。

**收藏夹** —— 按提醒日期排序，已处理的折到下面。

**日历** —— 月历视图，标出所有收藏岗位的提醒日，可翻月。

## 提醒日期是怎么定的

这是本软件唯一需要你参与判断的地方，原因是数据源的截止日期字段很脏。
对 208 条实测：

| 情况 | 条数 | 占比 |
|---|---|---|
| 完全没有 deadline 字段（全部 NBER 岗位） | 119 | 57% |
| 纯 rolling，无固定截止 | 50 | 24% |
| 只含日期 | 21 | 10% |
| rolling + 含日期 | 17 | 8% |
| 有文字但认不出日期 | 1 | 0% |

能抽出日期的 38 条里，11 条没写年份、19 条已过期 —— 也就是只有个位数的岗位
有干净可用的截止日期。格式还五花八门：`20th April 2026`、`5/24/26`、
`First review on 9/15/26, then rolling`、`Rolling with priority deadline of August 2, 2026`。

所以点 ☆ 收藏时会弹出一个面板：

- **原始截止信息**原样显示，让你自己核对；
- **程序判断**说明它是怎么读的（比如「原文没写年份，按最近的未来推断为 2027 年」）；
- **提醒日期**已经预填好 —— 抽到未来的日期就用那个日期，抽不到（rolling / 无字段 /
  日期已过期）就预填 7 天后；
- 一排快捷按钮（提前 3 天、就在截止日、14 天后……），或者直接改日期框。

回车确认，Esc 取消。

## 数据从哪来

`ingest.py` 读 `../mailer/state.json`，写进本目录的 `jobs.db`（SQLite）。
启动时自动同步一次，也可以随时点右上角「同步数据」。

**为什么要自己建库**：`state.json` 只存"当前在招"，岗位一下架就被删掉，
而且记录里没有"首次出现日期"。所以：

- **抓取日期（post date）** 由本软件在首次见到某岗位时打上，之后不再改动 ——
  这就是卡片上「抓取于 ○○」那个徽章；
- **已下架的岗位不会消失**，只标记为「已下架」留在历史列表里；
- 因此**历史是从本软件建库那天开始积累的**，之前的没法回填（邮件版的日志
  只记了每天新增的条数，没记标题）。

建库当天导入的存量岗位标记为 `is_initial`，不会在首页当成"新增"刷屏。

## 文件

```
app.py           HTTP 服务与路由（标准库 http.server，没有 Flask）
db.py            SQLite 表结构与查询
ingest.py        state.json -> jobs.db
deadlines.py     截止日期解析（脏数据全在这里对付）
templates/       jinja2 模板
static/          样式与前端脚本
jobs.db          你的数据：岗位、收藏、提醒（已 gitignore）
启动.bat         双击启动
```

## 排错

**打不开网页** —— 端口 8765 可能被占了，换一个：`app.py --port 8000`。

**提示「找不到邮件版的 state.json」** —— 它会依次找 `../mailer/state.json` 和
`../state.json`。如果邮件版被挪到了别处，改 `ingest.py` 顶部的 `STATE_CANDIDATES`。

**岗位数量不对** —— 点「同步数据」重新读一次。如果邮件版当天抓取失败，
它不会写坏 state.json（有护栏），本软件读到的就是上一次的快照。

**想清空重来** —— 删掉 `jobs.db` 再启动即可重新建库，但**收藏和提醒会一起丢**。
